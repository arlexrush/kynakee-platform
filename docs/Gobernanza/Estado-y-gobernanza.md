# Estado del repositorio y criterios de gobernanza

Este documento separa la **arquitectura objetivo** descrita en PRD, ADR, contratos, SAD y especificaciones del **estado observable del código**. La existencia de un proyecto, clase, contrato, Compose o prueba no demuestra por sí sola que una funcionalidad esté operativa. Ante una discrepancia sobre el estado actual, prevalecen el código y las comprobaciones reproducibles; las decisiones de diseño aprobadas siguen siendo requisitos para el trabajo pendiente.

## Cómo declarar el estado

- **Diseñado:** requisito o decisión documental; todavía no implica implementación.
- **Implementado en código:** existe una implementación concreta revisable, no solo un registro de DI, interfaz, esqueleto o `NotImplementedException`.
- **Compila:** se ha ejecutado una compilación con resultado satisfactorio y se indica el alcance (proyecto o solución). No equivale a comportamiento correcto.
- **Probado:** se han ejecutado pruebas identificables sobre ese comportamiento; una clase de prueba vacía o de plantilla no cuenta.
- **Operativo:** se ha comprobado el recorrido real con dependencias, configuración, datos y entorno previstos. Una definición Compose no demuestra un despliegue funcional.
- **Pendiente / no verificado:** falta evidencia para una de las categorías anteriores. No extrapolar resultados entre categorías ni entre módulos.

Para cerrar un pendiente, registrar el archivo y símbolo que implementa la regla, el comando de compilación y su salida, la prueba ejecutada y su resultado, y, si afecta a EF/infraestructura, el resultado de migración y prueba de integración o despliegue. Documentar fecha, entorno y limitaciones de cada evidencia. No convertir planes de Sprint 0 en hechos consumados.

## MCP: auditoría independiente y salud persistente (paso 6, parte 5)

**Evidencia del 2026-10-02:** .NET 10, PostgreSQL 17 efímero y proveedor HTTP simulado. Se registra automáticamente el resultado del cliente; no se acredita interoperabilidad con un proveedor real.

- **Implementado:** [ProviderNetworkClient.QueryPriceAsync](../../src/Kynakee.Modules/Kynakee.Modules.Mcp/Infrastructure/Client/ProviderNetworkClient.cs) genera un `McpQueryLog` por resultado final de servidor, después de reintentos. [McpQueryAuditWriter.WriteAsync](../../src/Kynakee.Modules/Kynakee.Modules.Mcp/Infrastructure/Client/McpQueryAuditWriter.cs) guarda los logs y actualiza salud mediante el agregado en un contexto/transacción independiente, suprimiendo la transacción ambiente. Usa `FOR UPDATE` y la columna de sistema `xmin` para serializar modificaciones de salud concurrentes. Escritura acotada por cancelación y timeout de 10 s; los errores de persistencia se propagan, no se ignoran ni se devuelve un éxito sin auditar.
- **Semántica:** una actualización de salud por recorrido del proveedor, no por reintento; éxito resetea fallos y registra `LastSuccessAt`, fallo remoto incrementa el contador y el tercero suspende. Circuito abierto y configuración local no penalizan al proveedor, aunque su resultado se audita. Cancelación del llamante se propaga sin registrar ese intento ni contar fallo. Los resultados se acumulan y guardan al finalizar el recorrido del proveedor; una cancelación antes de ese guardado puede dejar sin registrar resultados anteriores del mismo recorrido. Ausencia de proveedor e input inválido no generan log, porque no hay intento contra un proveedor identificable.
- **Tenant y contexto:** las consultas de precios requieren tenant y usuario autenticados; el log pertenece al consumidor, aunque el proveedor sea de otro tenant. `ProjectId` es opcional y local, no se transmite al servidor. La pertenencia del proyecto aún no se comprueba. El modelo de log actual no conserva `ServerId`, moneda ni código detallado de error; el resultado se distingue mediante estado, precio/unidad, confianza, duración y proveedor. No interpretar esta auditoría como trazabilidad completa por servidor.
- **Registro:** escritor concreto scoped registrado por `AddMcpModule`, llamado desde la composición global existente. No requiere cambios de esquema ni migraciones; no se aplicaron cambios a bases existentes.
- **Compilado y probado:** builds MCP e IntegrationTests correctos.
