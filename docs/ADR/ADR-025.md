## 1. Context

Kynakee is a multi-tenant SaaS platform for AI-powered construction budget generation. WhatsApp is defined as a primary user channel in ADR-014 (Bot Channel Architecture), enabling reformers, SMEs, and construction companies to create projects, capture site evidence, and receive offers directly from their mobile devices.

WhatsApp has no official .NET SDK. Three integration approaches were evaluated to determine the most appropriate strategy for the Kynakee platform, considering cost, complexity, control, and alignment with the credit-based economic model defined in ADR-013.

> **Key constraint**: Every message processed by the platform has a cost impact. The integration approach must minimize per-message overhead to preserve margin in the credit-based pricing model.

## 2. Options Evaluated

### Option A — Meta Cloud API Direct (Selected)

| Attribute | Value |
|---|---|
| Provider | Meta (Facebook) — official WhatsApp Business Platform |
| Cost | Free up to 1,000 service conversations/month. Per-conversation pricing beyond that (varies by country). |
| NuGet Package | **None required** — native `HttpClient` + `System.Security.Cryptography` (.NET 10 SDK) |
| Complexity | Medium — requires webhook implementation, HMAC-SHA256 validation, and Meta Business Account setup |
| Control | **Full** — direct access to all Meta WhatsApp Cloud API features |
| Vendor Lock-in | Meta only — no intermediary dependency |

### Option B — Twilio (Intermediary)

| Attribute | Value |
|---|---|
| Provider | Twilio — third-party communications platform |
| Cost | €0.005 per message + WhatsApp per-conversation fee. Adds intermediary markup on every message. |
| NuGet Package | `Twilio` 7.* — additional dependency |
| Complexity | Low — well-documented SDK, abstracts webhook complexity |
| Control | Partial — dependent on Twilio availability and pricing changes |
| Vendor Lock-in | High — Twilio SDK + Twilio account dependency |

### Option C — 360dialog (Intermediary)

| Attribute | Value |
|---|---|
| Provider | 360dialog — WhatsApp Business Solution Provider |
| Cost | €49/month per phone number + WhatsApp conversation fees |
| NuGet Package | None — HttpClient direct (similar to Option A but via 360dialog endpoint) |
| Complexity | Low — managed service, simplified setup |
| Control | Partial — dependent on 360dialog availability and pricing |
| Vendor Lock-in | Medium — 360dialog account dependency, monthly fixed cost |

## 3. Decision

**Option A — Meta Cloud API Direct is selected.**

Rationale:

- **Lowest operational cost** — critical for the credit-based economic model (ADR-013). Every saved cent per message directly improves platform margin.
- **No intermediary markup per message** — Twilio adds €0.005/message which compounds significantly at scale (e.g., 100,000 messages = €500 additional cost).
- **Full control over webhook processing** — enables custom retry logic, priority queuing, and direct integration with MassTransit Outbox (ADR-006).
- **No additional NuGet dependency** — uses native .NET 10 `HttpClient`. Reduces dependency surface and eliminates third-party SDK version conflicts.
- **HMAC-SHA256 webhook validation** via `System.Security.Cryptography` — included in .NET 10 SDK, no external package required.
- **Aligned with cost-first infrastructure strategy** — consistent with Hetzner (vs Azure/AWS), free Cloudflare tier, and self-hosted Docker approach.
- **Direct access to all Meta WhatsApp Cloud API features** — message templates, media messages, reactions, interactive buttons, and future API additions without waiting for intermediary support.

## 4. Consequences

### 4.1 Positive Consequences

- Zero per-message intermediary cost — only Meta's own conversation pricing applies.
- 1,000 free service conversations per month — sufficient for MVP and early adopter phase.
- No vendor lock-in beyond Meta itself — switching only requires changing the HTTP endpoint and authentication.
- Full API feature access — message templates, media, interactive messages, and all future Meta API additions.
- Consistent with platform architecture — webhook → YARP → Bots module → MassTransit → Project aggregate.
- Reduced dependency surface — no Twilio SDK to maintain, update, or audit for security vulnerabilities.

### 4.2 Negative Consequences and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Meta Business Account verification required | Medium — 1-3 business days delay | Start verification process in Sprint 0 |
| Webhook must be publicly accessible | Low — development friction | Use ngrok in development (ADR-020). Traefik handles staging/prod. |
| HMAC signature validation must be implemented manually | Low — development effort | Implementation covered in Section 5.2. Uses `System.Security.Cryptography`. |
| Rate limits on free tier | Low — 1,000 conv/month limit | Monitor via AI consumption tracking. Upgrade to paid tier when needed. |
| Meta API changes require direct adaptation | Medium — no intermediary buffer | Pin to stable API version (v19.0). Monitor Meta changelog. |
| No phone number portability if switching providers | Low — future risk | Document phone number in infrastructure registry. Acceptable risk for MVP. |

## 5. Implementation

### 5.1 Prerequisites

- Meta Business Account at [business.facebook.com](https://business.facebook.com)
- WhatsApp Business App created in Meta Developers Console ([developers.facebook.com](https://developers.facebook.com))
- Verified phone number — can be a virtual number. Must not be registered with personal WhatsApp.
- Public webhook URL — ngrok for development (ADR-020), Traefik + Hetzner for staging/prod.
- Meta App Review — required for production access to all message types. Development mode allows testing with up to 5 numbers.

### 5.2 Webhook Validation (HMAC-SHA256)

Meta sends a `X-Hub-Signature-256` header with every webhook POST. Validation is mandatory to prevent spoofed requests:

```csharp
// WhatsAppWebhookEndpoint.cs
// Uses System.Security.Cryptography — included in .NET 10 SDK
private static bool ValidateSignature(
    string payload,
    string signature,
    string appSecret)
{
    var key  = Encoding.UTF8.GetBytes(appSecret);
    var hash = HMACSHA256.HashData(key, Encoding.UTF8.GetBytes(payload));
    var expected = "sha256=" + Convert.ToHexString(hash).ToLowerInvariant();

    // Use constant-time comparison to prevent timing attacks
    return CryptographicOperations.FixedTimeEquals(
        Encoding.UTF8.GetBytes(expected),
        Encoding.UTF8.GetBytes(signature));
}
